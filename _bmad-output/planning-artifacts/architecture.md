# Technical Architecture: Talambralu

## 1. System Overview
Talambralu is architected as a **Modular Monolith** deployed on AWS. This design balances development velocity with a clear path toward microservices.

### Key Architectural Constraints:
- **Logical Isolation:** Modules must not depend on each other's internal implementation.
- **Data Sovereignty:** Each module owns its schema. Cross-module SQL joins are strictly forbidden.
- **Communication:** Synchronous inter-module calls via NestJS Services (interfaces); Asynchronous via in-memory events or AWS SQS.

## 3. Module Decomposition & Domain Boundaries

### 3.1 Auth Module
- **Responsibility:** Identity management, session validation.
- **Integration:** Firebase Auth (Identity Provider).
- **Interface:** `AuthService.validateToken(token: string): Promise<UserSession>`

### 3.2 Profile Module
- **Responsibility:** Comprehensive user data, media references, partner preferences.
- **Data Ownership:** `users`, `profiles`, `user_photos`, `preferences`.
- **Search:** Native PostgreSQL `tsvector` indexing on profile attributes.

### 3.3 Verification Module (The Moat)
- **Responsibility:** Orchestrating multi-step verification pipelines.
- **Integrations:** AWS Textract (Paystubs), Amazon Rekognition (Liveness), AWS SES (Work OTP).
- **Process:** S3 Upload -> SQS -> Textract -> DB State Update.

### 3.4 Match Module
- **Responsibility:** Double opt-in state machine.
- **Data Ownership:** `interests`, `matches`, `shortlists`.
- **Constraint:** Chat can only be initiated if a `match` record exists.

### 3.5 Communication Module
- **Responsibility:** Real-time text chat and A/V coordination.
- **Tech:** NestJS WebSockets + Redis Pub/Sub for horizontal scaling.
- **Integration:** Amazon Chime SDK for A/V signaling.

### 3.6 Subscription Module
- Responsibility: Managing user entitlements, premium status, and receipt validation.
- Integration: RevenueCat SDK (Client) & Webhooks (Server-to-Server). Native Apple App Store and Google Play Billing infrastructure.

## 4. Data Model (High-Level Schema)

### Profile Table
```sql
CREATE TABLE profiles (
  id UUID PRIMARY KEY,
  user_id VARCHAR UNIQUE NOT NULL, -- Firebase UID
  full_name TEXT NOT NULL,
  dob DATE NOT NULL,
  gender gender_type NOT NULL,
  location_lat_long POINT,
  income_bracket_id INT REFERENCES income_brackets(id),
  visa_status_id INT REFERENCES visa_statuses(id),
  search_vector TSVECTOR, -- For optimized discovery
  is_face_verified BOOLEAN DEFAULT FALSE,
  is_work_verified BOOLEAN DEFAULT FALSE,
  is_income_verified BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Match Table
```sql
CREATE TABLE matches (
  id UUID PRIMARY KEY,
  user_a_id UUID NOT NULL,
  user_b_id UUID NOT NULL,
  status match_status DEFAULT 'PENDING',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_a_id, user_b_id)
);
```

## 5. API Strategy (REST & WebSockets)

### Consistent Error Format
```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "Validation failed",
    "details": { "field": "dob", "issue": "Under 18" }
  }
}
```

### Key Endpoints
- `POST /v1/profiles`: Create/Update profile.
- `GET /v1/discovery`: Paginated search with filters.
- `POST /v1/interests`: Initiate interest in another user.
- `GET /v1/chat/messages/:matchId`: Paginated message history.
